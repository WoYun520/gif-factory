# 从对标里提取方法

## 两种抽帧解决两种问题

- 4–6fps总览：事件先后、角色位置、场景何时入画、哪里停了多久。
- 原帧率局部：预备动作、触碰、受力、释放、耳朵等延迟反应。总览抽帧会漏掉关键接触，不能只看它宣布自然。
- 连续播放：能否看懂、是否拖、是否像在换图。静态拼图好看不代表播放通过。

`inspect_reference.py` 的时间标记为采样网格，用于定位，不替代源视频原帧时间。脚本只采样和做表，不评价自然度。原片、重建、观察结论分开留存。

## 已观察到的邮差案例

用户提供的纸艺邮差原片为1920×1080、24fps、260帧、约10.83秒，无音轨。前三个屋子属于同一条路线。人物骑行、短暂停靠、住户交接，再继续走；后段人物抬头/转面，把注意力交给鸟和月亮，最后落纸牌。

| 可迁移的做法 | 怎么用到新故事 | 不能据此推断 |
| --- | --- | --- |
| 行动贯穿，局部有停顿 | 一条明确的任务路线；停靠时演一个可读事件 | 所有故事必须骑车或11秒 |
| 下一地点提前在场 | 场景图上先排出地点/配角/物件的位置 | 必须三间屋或同样的太阳月亮 |
| 移动与表演互相接力 | 行进、减速、手的接触、回收、再走分别设计 | 匀速平移或全片一种正弦晃动即可 |
| 角色有正侧转向与躯干变化 | 动作表记录视图/重心，按需要准备脸与身体视图 | 单张侧身旋转、4张姿态叠化等价 |
| 交接有住户反应 | 接收者先在场，手接触，道具换持有者，再离开 | 信件独立飞向门就算交接 |
| 末段注意力交给鸟 | 主角动作收住，再由小动作完成回报 | 任何时候都要增加同时运动的元素 |

不能从成片断言原作者使用代码、骨骼、逐帧或视频模型。库的工具和制作说明可以参考；模型或软件的选择仍需当前任务验证。

## 本项目的反例

- 送灯24秒：剧情因果增加了，但在同一棵树边停太久，同一侧身用单臂旋转硬演捞取和交接。用户评价“太僵硬”。
- 送灯14秒：缩时并增加4张上身姿态，仍是换图叠化与独立道具轨迹。用户评价“不自然”。因此“再多几张姿态”不是已验证修复。
- 邮差重建：事件顺序、骑行关节求解和24fps文件已完成，动作审美尚未获认可，屋距/构图/角色比例与原片仍不同。不要把技术检查通过当成复刻成功。

## 可复用的生产顺序

先写动作与接触关系 → 做动作小样 → 在同机位与原参考比较 → 通过后接场景和故事 → 再定声音、帧率与输出。

故事复杂时先检查当前方法是否能表现抓、捞、递和转向。不能先加剧情，再用不具备这些能力的贴图动画硬凑。先验证一个最难接触，不等于后续每个动作都自动通过。

## 复用拆解工具

从技能目录运行：

```sh
python3 scripts/inspect_reference.py reference.mp4 --out review/overview --sample-fps 6
python3 scripts/inspect_reference.py reference.mp4 --out review/contact --start 1.4 --duration 1.5 --sample-fps 24
```

第二条的起点、范围和帧率按实际原片调整；24fps不是固定值。采样高于源帧率只会重复帧，不会补出动作。`--out` 使用新或空文件夹，避免混入旧帧。默认最多180帧，长片可缩小范围或显式设置 `--max-frames`。需要本机 ffmpeg、ffprobe、Python 3 与 Pillow；不上传原片。

`reference.json` 记录真实视频规格、有无音轨、采样范围/数量和待验收状态；不写入个人绝对路径。`sheet-*.jpg` 每张最多16个带时间标记的采样图。脚本只确认抽帧完成，视觉与用户验收默认保留待检查。

方法来源：用户提供的纸艺邮差参考与本地失败试作；导演组织另参考 [Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar) 的导演指南。这里是面向本工作流重新组织的实验检查法，不是原作者制作步骤的取证，也不捆绑其整库或要求其专用环境。
