# 金融纸艺科普

把观众不熟悉的一个金融机制，变成能看见的人物、物件、动作和结果。第一版以《贷款创造存款》为样例：柜台签约、两份凭证、天平账本、盖章还本、跨行结算。复用它的场景叙事和阅读节奏，不把银行、100万元或六个镜头强加给所有题目。

这是制作方法与检查工具，需要可用的图像生成、配音及视频渲染环境；安装本 Skill 不会附送模型、服务额度或渲染器。公开版默认无个人水印、无固定作者名、无强制系列名。

## 接续用户的要求

- 只要选题或方案：给最有把握的切入点、开头问题和可拍的场景，先不制作整片。
- 已批准“可以”“开始”或明确要求制作：沿用当前选题、素材、声线和格式，继续做到可看的成片，不重复要求确认同一方案。
- 反馈“画面简陋”：检查主动作、人物互动、景别、前中后景和物件关系。改场景内容，不只增加标题、图标和转场。
- 修改已有片：先读当前工程与最新验收记录，只改用户指出的内容。画面修改可复用已有旁白，不重新发送配音请求。

## 叙事与风格

先看 [场景与视觉规格](references/scenes.md)，需要实际观感时打开 [六场画面参考](assets/visual-reference.jpg)。

开头直接呈现与普通人有关的问题，例如“银行借给你的100万，从哪来？”随后用同一笔交易讲清操作、两边账目、反直觉结果和边界，最后回到最初问题。少用术语定义开场，不用夸大损失、阴谋论或编造收益制造冲突。

每个解释点安排一个可见动作：签、递、记、扣、盖、划转、抵达。让人物正在做事，物件有接触点和前后状态。营业厅中景、交易桌面、账本近景、地图可以交替使用；新题目按实际业务换成收银台、商户、订单、交易席等场景。

黑纸、暖白撕边、灰度摄影与少量黄色强调；字和数字在工程里排，不让生图模型生成关键文字。底图延伸填满画面，关键内容留在手机可读区域。主数字够大，连续两三张镜头不要只是同一站立人物加同款数字卡。

默认主片1080×1920、30fps，约40–60秒起步，复杂机制可按内容延长；用户要求与已有工程优先。不要为了凑时长延长空镜，也不自动追加方形、横屏或GIF交付。

## 金融内容要跟得上画面

先核实机制，记录支持关键说法的官方来源、适用范围和查询日期。涉及实际产品、费率、法规或新闻时查当前材料。不能把某个国家的制度或某家产品的条件写成普遍事实。

同一份数据驱动旁白、金额、路线和最终余额。钱涉及谁、流向谁、是本金还是利息、是收入还是利润，都要明确。用整数最小货币单位计算，未知数保留未知。关系相等时两处计数器共用起止值和时间，结尾沿用实际末态。

必要假设放进旁白、对应步骤标签和工程说明，不在画面底部反复加“虚构案例”等通用注释。画面中不显示配乐署名条；音乐优先选用户可用、原创或无需署名的素材，需要署名时随工程附可直接使用的发布文案与完整来源。

## 制作与交付

具体顺序、配音、图片、渲染与导出见 [制作与检查](references/production.md)。需要新图时再读 [素材提示词](references/prompts.md)。

以真实旁白的分句或逐词时间安排入账、盖章、减数和结算动作，别用字数估计代替最终时轴。配音跟随当前用户选择，外部服务的使用依当前对话授权，不把案例中的授权写成对所有人的默认许可。

HyperFrames 可用时读取环境中的对应技能并沿用已有工程固定版本。每场独立可编辑，字幕、场景、音频分层，所有变化能按时间直接定位。仅检查通过不代表观感合格：看手机尺寸、切点、接触动作和实际导出帧。

交付主片、同风格封面、可编辑工程和必要素材说明。公开视频与封面默认无个人水印，不加底部案例条或配乐署名条；必要机制范围通过旁白或步骤标签交代。用户明确要求品牌时才加。没有实际导出文件时，明确当前只完成了脚本或分镜。

使用 `scripts/inspect_delivery.py` 检查实际文件：

```bash
python3 scripts/inspect_delivery.py film.mp4 --duration 42.733333 --cover cover.png --archive project.zip --full-decode
```

该命令检查尺寸、帧率、帧数、时长、音轨、封面和ZIP，可选择全片解码；不代替金额审计、视觉验收或人耳试听。技术检测与人工听审分开说明。
